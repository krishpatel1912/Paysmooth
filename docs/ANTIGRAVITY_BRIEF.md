# PaySmooth: Antigravity Brief

## What this project is
PaySmooth is an AI income-smoothing app for Indian gig workers (delivery riders). It forecasts weekly income, splits it into buckets (rent, EMI, tax, emergency, spendable), simulates "what if I skip N days?", and gives a coach message in Marathi/Hindi/English using Gemini. Data is simulated (data/riders.json). This is a hackathon demo, so working and polished beats feature-rich.

## Stack
- Backend: Node.js + Express (ES modules), port 5000, folder /server
- Frontend: React + Vite + Recharts, port 5173, folder /client (Vite proxies /api to :5000)
- AI: Gemini via @google/generative-ai, key in GEMINI_API_KEY (server/.env)
- Data: data/riders.json generated by scripts/generateData.js

## API contract (must not change)
- GET  /api/riders -> [{id,name,city,platform}]
- GET  /api/riders/:id/summary -> { rider, history:[{date,amount}], forecast:[{date,predicted,low,high}] (7 days), buckets:{rent,emi,tax,emergency,spendable}, safeDailySpend }
- POST /api/simulate {riderId, skipDays} -> { baselineWeekly, adjustedWeekly, shortfall, emiAtRisk, emergencyImpact }
- POST /api/coach {riderId, language} -> { message }

## Rules
1. Do NOT rewrite from scratch. Fix and improve existing files only.
2. Do NOT add new features beyond the 4 core ones: forecast, buckets, simulator, coach.
3. No investment advice anywhere in the UI or prompts.
4. Keep the app working without Firebase. Firebase is optional.
5. Never hardcode secrets. Use .env files and keep .env.example updated.
6. Keep changes small and explain each fix in one line.
7. Be economical: don't re-read unchanged files, and batch related fixes.

2. Verify all 4 endpoints match the contract above. Fix any mismatch in code or docs.
3. Use the browser agent to test: switch riders, move the simulator slider 0 to 7, click the coach in mr/hi/en. Fix bugs, including the case where the Gemini key is missing (the fallback message must show).
